日期：2026-11-17。触发：用户指路 E:\lscshz（网易炉石盒子安装目录），问有无可参考功能。
性质：设计层参考，不抄代码、不抄实现方式。

## 本地取证（E:\lscshz，420M 编译客户端）

- NeteaseHSMatch.dll → 对局/记牌数据模块；NeteaseHSRecord.dll + hsaplugins/VideoPlugin.dll
  + VideoEditor.dll → 录制+剪辑（战斗回放/高光）。
- heart_overlay.dll / heart_overlay_x64.dll 内引用 hshook_overlay_x86/x64.dll →
  游戏内悬浮窗=**hook 注入游戏进程**实现（我们不抄，见红线差异）。
- audio_sniffer.dll + install_audio_module.bat：bat 原文 "Install video component" +
  regsvr32 注册 audio_sniffer → 录制用的**游戏声音采集组件**（不是语音聊天）。
- LiveMessage.dll / MessagePush.dll / livemsgsdk.dll → 直播消息推送（与我们无关）。
- CEF 壳（libcef/browser.exe/pages）；resources.pak 与 HSAng.exe 内**零中文功能字符串**
  （utf8/utf16 双扫）→ UI 内容在云端网页，本地只有模块骨架。功能语义靠模块名+公开清单互证。

## 公开功能清单（搜索互证）

记牌器（双方剩余牌/坟场/牌库数、对手手牌与奥秘预测）、竞技场助手（三候选 0-100 AI 评分：
卡牌质量/曲线/职业相性）、胜率统计（自动收集对局→职业/卡组胜率+局后报告）、战斗回放、
卡组推荐/一键导入、**酒馆战棋智能AI（英雄选择优先级、强势流派适配、每回合棋子购买与升级规划）**。

## 映射到卫戍协议AI（按参考价值排序）

1. **战棋AI的每回合购买/升级规划**＝与我们同范式（auto-chess）。参照其输出形态：
   每回合给"买/刷/升本/冻结"规划+流派适配建议。它靠云端大数据统计，我们靠本地结局驱动——
   范式相同（对局结果统计→推荐），佐证主引擎路线选型。
2. **竞技场助手的评分+排序+理由** → 商店推荐显示形态：每槽候选给分数+理由
   （质量/路线协同/节奏），不给单一答案。规则 baseline 先出分，NN 后期接管；
   "理由"字段正是用户纠正需要的接口。纳入 P1 商店区设计。
3. **战斗回放+VideoEditor** → 按回合自动切复盘片段：rounds 边界+scenes 已备，
   切 video.mp4 成每回合 clip，用户点回合号看当回合 → 解决"失误在哪回合"的标注入口
   （现在只有口述）。纳入 P3 配套工具。
4. **记牌器"已见→剩余池推断"** → 饥饿监控升级方向：从"N 回合未见核心"硬阈值升级为
   观测抽卡台账+可得性推断。**前提=有限公共牌池；规则书§3.2 只写刷新机制、无池量数值 →
   前提待证**（局内面板或用户知识）。若池无限/每人独立则退化为经验出现率统计（台账仍有用）。
5. **胜率统计/局后报告** → route_tag × outcome 的路线胜率/平均回合 dashboard＝
   数据集管理+路线先验。meta 标签已备，纯聚合工程。
6. **悬浮窗 UX** → assistant-first 推荐面板：紧凑、相位感知（rest 商店建议/combat 血线预览）、
   热键切换。**实现不抄**：独立置顶透明窗、零注入（hook 注入碰反作弊风险，红线）。
7. **audio_sniffer** → 录制加游戏音轨（ffmpeg 音频采集）：复盘听技能/漏怪 cues，
   远期音频事件辅助场景边界。低成本可选项。

## 红线差异（明确不抄）

- hshook 注入式 overlay → 我们零注入置顶窗。
- 云端大数据统计 → 我们本地小样本结局驱动（数据量级不同，范式同）。
- 盒子读炉石日志/注入取数 → 我们屏幕 OCR only（方舟无明文日志可用；不读内存/封包红线不变）。
