## 2. 措辞修正（B spec 层，非 schema 变更）

- **C1 字段名**：replay 逐条对齐标记字段 = **`input`**（值 "HUD-only"/"MOCK"，replay.py L60），
  不是 `degraded` 布尔；degraded 回合列表仅 print 到 stdout 不入 jsonl。B §1/§3.2「degraded 标」→
  报告生成器读 `input` 字段，局头 degraded 占比 = input=="HUD-only" 回合数/总回合数。
- **C2 flag 文案**：实际 flag 文本 = "非常规路线"（shop_score L133），策划案红线要求的完整警示
  「非常规路线，可能会失败」未全量落地——**我 lane 的 v0 缺口**，随报告生成器批次补全（flag 或
  reasons 带完整文案）。B 的 risk_flag 子串匹配（含「非常规路线」）两种文案都兼容，UX 不受影响。
- **C3 结局字段语义**：B §3.2「life_incoming（扣血）/预览 −M」把两件事并列了——实际
  **life_incoming = 伤害预览 −M token 本身**（parse_hud L10/117，预测扣血）；**实际扣血** =
  rounds.json life_start−life_end（L253-265）或 curves life 跨回合差。报告「回合结局」列建议
  预览/实际双呈现（35/35 回合预览==边界扣血已交叉验证，两者背离本身就是信号）。字段均既有，无 schema 变更。

## 3. 实现注记（报告生成器归 A，以下在实现层处理，不改 schema）

- **O1 rec_id 漂移与 ratings join**：state_hash 入 hash 字段含 shop/field/bench/funds/center_level
  （state.py L60-68）→ P1 商店 OCR 落地后重跑 replay，同回合 rec_id 必漂移 → 旧 ratings 严格按
  rec_id join 会孤儿化。**join 策略：rec_id 精确匹配优先，fallback 解析 rec_id 前缀
  `{session}:r{round}:`**（前缀自带 session+round，无需新增关联字段）。B §4③「无需新增关联字段」
  结论成立，但实现必须带这个 fallback，否则 P1 升级丢评分历史。
- **O2 score 跨 action 语义不齐**：buy=效用分 / upgrade=价格 / refresh=EV / freeze=0，统一降序
  （advisor L54）数值不可直接互比（升本价 13 会排在效用 8 的 buy 前）。报告展示层按 action 类型
  标注语义或分组展示，防用户按统一分数误读。schema 不变；v0.1 是否归一化排名另提方案（我 lane）。
- **O3 replay coop 门控 bug（我 lane，已修）**：B §2.3「coop 不产 rec→复盘天然只单机」对 live
  advisor 成立，但 replay.py 原实现未读 meta.mode_tag，from_curves_row 默认 solo → coop 会话
  （200142/205833）离线回放会绕过门控误产 solo rec（合并生命/漏怪桶污染推荐）。**已修**：
  replay() 读 raw meta.json mode_tag（目录约定同 parse_settlement）传入 from_curves_row，
  coop 时 advise 逐行 None + 打印门控提示；meta 缺失默认 solo 向后兼容。py_compile 过。
  这是 B spec 依赖的门控在 replay 路径的落实，spec 本身无需改。
