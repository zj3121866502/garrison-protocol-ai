## 1. 冻结 schema 摘录（锚点，B 不改）

**recs.jsonl**（advisor.py advise() 实际写出，line 55-60）：
```
{session, t, round, rec_id, state_hash,
 options:[{action, name?, score, reasons, flags, parts?}], top_k,
 checks, plan_notes, hard_veto}
```
- rec_id = `{session}:r{round}:{state_hash}`（回合+局面唯一键，评分绑定用）。
- options 四类 action：`buy:{name}`（带 name/score/reasons/flags/parts）、`upgrade`（score=price）、
  `refresh`（score=ev）、`freeze:{n}`（score=0，flags=["试探"]）。按 score 降序，取 top_k。
- flags 含「临时值」（C/D 级数值）/「非常规路线，可能会失败」/「试探」。
- checks=战斗覆盖清单（红黄绿）；hard_veto=红检查否决标志。**hard_veto 不可被评分 override**（advisor docstring line 7-8）。
- coop / round=None → advise 返回 None（v0 单机门控，不产 rec）。

**ratings.jsonl**（反馈环笔记 line 29，GUI/复盘侧后写）：
```
{rec_id, score, correction?, followed(yes/no/partial), risk_flag, rated_at}
```
- score=1-10；correction?=用户文字/替代动作（可选，稀疏高价值）；followed=用户是否照做；
  risk_flag=非常规路线分桶标；rated_at=评分时间戳。

**replay 输出**（replay.py，replay_recs.jsonl）：每回合一条 rec（首个 rest 相位行=决策窗），
额外附 `user_clicks_in_round`（该回合点击**计数**，来自 rounds.json）；逐条附 **`input` 字段**（值 `"HUD-only"`/`"MOCK"`，replay.py L60）标记对齐粒度，degraded 回合列表仅 print stdout 不入 jsonl（C1）。
**P1 前对齐粒度=粗**：只有点击数，无点击→动作语义、无商店 OCR →「买没买推荐干员」不可知（反馈环笔记 line 30-31）。

## 2. 评分 UX 流程

### 2.1 两种模式（批量复盘为主，实时为辅）

**A. 批量复盘评分（主推，省且准）**：局后/回合结束后进入复盘模式，逐回合回放
「当时推荐 vs 实际局面/结局」，用户一键 1-10 + 可选文字纠正 + followed 自评。
理由：实时评打断打牌、信用分配模糊；复盘有结局上下文，评分更准（反馈环笔记 line 39）。

**B. 实时评分（可选，≤1 次/回合）**：推荐窗每条 rec 旁挂迷你评分条（1-10 滑块/数字键），
用户愿意才点；**跳过 ≠ 差评**（不写 ratings 行，而非写低分）。回合内最多评 1 次防疲劳。

### 2.2 评分交互步骤（映射冻结字段，不新增）

1. UI 按 rec_id 显示对应推荐（top_k options + score + reasons + flags + checks），
   **信用分配明确**：回合级评分只作弱信号，优先评到具体 rec_id（反馈环笔记 line 46-47）。
2. 用户给 score（1-10）→ 写 ratings.score。
3. 可选 correction（文字框/「替代动作」选择）→ ratings.correction。空=不写该键。
4. followed 三态（yes/no/partial）→ ratings.followed。**P1 前由用户自评**（无商店 OCR 不能自动判定）；
   P1 后可由对齐管线自动建议 followed，用户确认/覆盖（仍写同一字段，不改 schema）。
5. risk_flag：rec.flags 含「非常规路线」时 UI 自动置 risk_flag=true（分桶用，学用户风险偏好≠推荐质量，
   反馈环笔记 line 50-51）；用户可手动改。
6. rated_at=写入时间戳。落 ratings.jsonl（append，与 recs 同目录 data/feedback/）。

### 2.3 红线与防学坏

- **hard_veto 不可 override**：红检查（对空缺口/阻挡不足等）否决的经济动作，UI 标红且评分条禁用「翻案」；
  用户自谦把保命检查评低 → 校准侧硬底线过滤（calibrate 默认只报告不应用，--apply 需≥20 样本，交接§4）。
- **试探标**：freeze/非常规推荐打「试探」，用户偏离的回合保留 off-policy 结局对照，防自证循环（反馈环笔记 line 48-49）。
- **联机**：v0 advise 对 coop 返回 None，不产 rec → 复盘评分天然只单机；联机推荐后置时私人提示不遮倒计时。
- **零注入**：评分 UI 只读 recs/写 ratings，不向游戏注入任何输入；用户照着推荐手动操作，操作被录制器记录。

### 2.4 校准衔接（A 的 calibrate，B 不写）

评分×结局一致性加权（反馈环笔记 line 22-23）：偏离推荐且结局好=强信号；评分高结局差=降权；
评分低但照做且结局好=评分口径问题回访。权重更新=离线批处理+漂移报告给用户审，不静默改权重。
B3 只保证 ratings 字段够喂这套逻辑（已够：score/correction/followed/risk_flag + rec_id  join recs + curves 结局）。

## 3. 3 局回放对照报告格式 spec

### 3.1 定位（红线）

报告=**给用户判合理性的对照材料**，不是自动 pass/fail 验收 harness（档1§6 步骤4）。
输出「推荐 vs 用户实际 + 结局」逐回合对照，用户读完自行判「模型这步建议合不合理」，
纠正写回 ratings.correction。报告不宣布「模型对/错」，只呈现证据。

### 3.2 数据源与 join（全用既有字段，不重定义）

| 来源 | 提供 | join 键 |
|---|---|---|
| replay_recs.jsonl（replay.py） | 每回合 rec（options/score/reasons/flags/checks/hard_veto）+ user_clicks_in_round + degraded 标 | session+round |
| curves.jsonl（parse_hud） | life_incoming=**伤害预览 −M token 本身**（预测扣血，L10/117）；covenants/enemy_total/phase。**实际扣血另见 rounds.json life_start−life_end**（C3：预览/实际双呈现，背离即信号） | session+round |
| rounds.json | 回合点击计数（已并入 replay 的 user_clicks_in_round） | round |
| ratings.jsonl（若用户已评） | score/correction/followed/risk_flag | rec_id |
| meta.json | 结局胜负/难度/route_tag/mode_tag | session |

**P1 前缺**：商店 OCR（实际买了谁）、点击→动作语义（实际买/卖/刷新/升本）、阵容 → 报告对齐粒度=粗（见 3.4）。

### 3.3 报告结构（每局一份，3 局汇总一份）

**局头**：session id / mode_tag / 难度 / route_tag / 最终胜负 / 总扣血 / 回合数 / degraded 回合占比。

**逐回合对照表**（每行一回合，核心交付）：
```
回合 | 推荐 top-N（action+score+关键 reason+flags） | 战斗清单 checks（红黄绿）+hard_veto
     | 用户实际（P1前=点击数 user_clicks_in_round；P1后=买/卖/刷新/升本语义）
     | 回合结局（扣血 life_incoming / 预览 −M / 盟约层变化）
     | 用户评分（score/followed/correction，若已评；未评留空≠差评）
     | 对照标记（见 3.4）
```

**局尾小结**：模型推荐与用户操作的一致/偏离回合数（P1 前仅点击量级粗对照）、
红检查触发回合、非常规路线回合（risk_flag 桶）、degraded 回合清单（数据不足以下结论的回合明确列出）。

**3 局汇总**：跨局 recurring 盲点（如「重经济轻对空」反复出现）、评分分布、偏离且结局好/差的回合清单
（off-policy 强信号）、给用户的「哪些推荐值得复盘」引导（不替用户下结论）。

### 3.4 对齐粒度诚实分级（P1 前关键）

- **粗对齐（P1 前，现在 3 局旧样本属此级）**：只有 user_clicks_in_round（点击数）+ HUD 结局。
  能对照：推荐了买 X / 该回合用户点了 N 次 / 结局扣血 M。**不能断言**「用户买了 X」或「用户没听推荐」
  （点击数 ≠ 动作语义）。报告对照标记只能给「点击量活跃/清淡」+「结局好/差」，**不给「跟随/偏离」判定**。
  followed 字段 P1 前靠用户复盘自评，报告不自动填。
- **细对齐（P1 后）**：商店 OCR + 点击语义落地 → 实际 buy/sell/refresh/upgrade 可知 →
  报告可给「推荐 buy:X vs 实际 buy:Y」逐动作对照 + followed 自动建议。degraded 回合消失。
- 报告每局头注明当前对齐粒度（粗/细），degraded 回合逐条标「数据不足，仅供用户参考，不作模型对错结论」。

### 3.5 结局连接（客观信号对冲技能天花板）

回合结局（扣血/预览/胜负）来自 curves，客观。报告把「用户偏离推荐（P1 后细对齐可知）且结局好」
标为 off-policy 强信号（反馈环笔记 line 22）；「评分高但结局差」标存疑。P1 前结局仍可用（扣血/胜负已知），
只是「偏离」不可自动判 → 结局列照常呈现，偏离判定留用户复盘。
