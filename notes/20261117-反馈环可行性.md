# 反馈环可行性：模型试探性推荐 + 用户打分纠正 + 观察实际操作

2026-11-17。用户原话："模型刚创建的时候，可以尝试性提出建议，我来负责评分和纠正
（比如1-10给他打分，然后它看我具体是怎么操作的），你这轮顺便思考下可行性。"

## 结论

**可行，而且边际成本很低。** 感知+录制管线已经备齐"用户实际做了什么"
（clicks + 帧 + HUD 曲线），缺的只是"模型当时推荐了什么"的日志——
档1 推荐窗正好产出这份日志。所以这个环不是新系统，是把已有两半接起来。
建议作为档1 的"反馈通道 v0"一起建，不等 NN 阶段。

## 四种信号，价值各不同

| 信号 | 性质 | 用途 | 局限 |
|---|---|---|---|
| 用户评分 1-10 | 即时、密集、便宜 | 档1 权重校准；盲点检测（如模型重经济轻对空=用户自己那次致命失误） | 编码的是用户水平，不是最优解 |
| 用户纠正（文字/替代动作） | 监督目标，比标量强 | 该状态下的更优动作 → BC 目标 / 偏好对 (推荐, 纠正) | 稀疏，靠用户愿意写 |
| 观察到的实际操作 | 免费、无负担的显示偏好 | 一致性核对 + 结局连接 | 混杂：忽略/手滑/试验/挂机 ≠ 否定推荐 |
| 回合结局（已有：扣血/预览/胜负） | 延迟但客观 | 对冲前三者的技能天花板 | 归因噪（联机队友、波次随机） |

组合规则：评分 × 结局一致性加权。用户偏离推荐且结局好 = 偏离被结局验证（强信号）；
评分高但结局差 = 存疑降权；评分低但用户照做且结局好 = 评分口径问题，回访。

## 落地机制（档1，无 NN）

- `recs.jsonl`：{session, t, round, rec_id, state_hash,
  options:[{action, score, reasons, flags(临时值/非常规路线)}], top_k}
- `ratings.jsonl`：{rec_id, score, correction?, followed(yes/no/partial), risk_flag, rated_at}
- 对齐：rec 时间窗内用 clicks + 商店 OCR 提取实际动作。**商店 OCR 是 P1**，
  所以 P1 之前对齐是粗的（"买没买推荐干员"不可知）→ 评分环先行，自动对齐随 P1 落地。
- 权重更新 = **离线批处理**（每 N 局/每周），拟合档1 评分权重 w 使推荐与
  "纠正 + 结局过滤"后的一致度最大；产出**权重漂移报告**给用户审——不静默改权重。
- 战斗覆盖检查单（对空/阻挡/DPS/特训）= 硬底线，评分不可 override：
  防止用户自谦"菜鸡"把保命检查评低后模型学坏。

## UX 约束（红线兼容）

评分可选、不阻塞：回合结束后或局后复盘模式批量补评（回放推荐 vs 实际，比实时评更省更准）；
一键 1-10 + 可选文字；跳过 ≠ 差评；联机不遮决策倒计时（私人提示红线不变）。

## 风险与对策

- 技能天花板：用户评分/操作 ≠ 最优 → 结局加权 + 硬底线（上）。
- 评分疲劳：可选 + 批量复盘评；每回合实时评最多 1 次。
- 信用分配：回合末的分指哪条推荐？rec_id 绑定 + 评分时 UI 显示对应推荐；
  回合级评分只作弱信号。
- 自证循环：推荐→用户跟随→好结局→高分→强化模型自己的先验。
  对策：试探性推荐打「试探」标；用户偏离的回合提供 off-policy 结局信号，保留对照。
- 极端路线：非常规推荐失败被评低 ≠ 推荐错（风险已标注）→ risk_flag 分桶分析，
  学的是用户风险偏好，不是推荐质量。
- 联机归因噪：结局含队友贡献 → mode 标签分桶，校准权重单机为主。

## 与后续阶段衔接（战略价值）

档3 NN：(state, rec, score) → reward/偏好头；(state, 纠正动作) → BC 预训练；
结局 → RL 微调。**偏好数据集从第一天累积，事后无法 retro-fit**——
现在建日志的最大价值是为档3 存料，档1 自身也立刻受益（权重校准）。

## 本轮决定

日志 schema + 评分 UI 纳入档1 推荐窗设计（model/advisor 实现时一并写）；
自动对齐随 P1 商店 OCR；权重校准离线批处理 + 漂移报告。不改任何红线。
